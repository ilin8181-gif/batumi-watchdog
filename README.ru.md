# batumi-watchdog

Облачный сторож сайта на GitHub Actions (бесплатно, 24/7, независимо от вашего компьютера).

Каждые 30 мин проверяет 3 слоя и шлёт в Telegram **только на смену статуса** (лёг/поднялся):

1. доступность — HTTP-код + тело (есть `</html>`, нет маркеров краха, размер не обвалился);
2. индексируемость — не просочился `noindex`, robots не `Disallow:/`;
3. дрейф — sitemap не просел против бейзлайна более чем на 30%.

## Зачем это

WP fatal под кэшем отдаёт **HTTP 200 с телом «критическая ошибка»** — простой пинг
«200=живой» это пропускает (так одна поломка прожила ~3 дня). Сторож ловит маркеры
краха в теле, обрыв страницы и случайно просочившийся `noindex`.

## Быстрый старт

1. Сфоркните репозиторий (или скопируйте `watchdog_ci.py` + `.github/workflows/watchdog.yml` к себе).
2. Секреты (**Settings → Secrets and Actions**):
   - `TG_TOKEN` — токен Telegram-бота;
   - `TG_CHAT` — chat id владельца.
3. Ваш сайт — переменная окружения `WATCHDOG_SITE` в workflow (по умолчанию
   `https://batumi-expert.ru`); пути/маркеры/мин. размер тела правятся прямо в `watchdog_ci.py`.
4. (опционально) зафиксируйте базлайн sitemap в `state/watchdog_state.json` (`sitemap_count`).

State между запусками — через `actions/cache` (rolling). Ручной запуск — вкладка Actions → Run workflow.
